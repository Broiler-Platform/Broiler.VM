# half           core-result  the code travels in a core verification result, in the profile
#                             diagnostic-code field, beside a core reason and a position. It is
#                             declared by JavaScriptDiagnosticCode, in the profile assembly.
#                embedder-seam  the code is carried by a rejection of SOURCE, which never becomes
#                             an artifact and never crosses a core result envelope. It is declared
#                             by SliceSourceDiagnosticCode, in the lowering assembly. THE TWO
#                             HALVES ARE TWO VOCABULARIES IN TWO ASSEMBLIES THAT DO NOT REFERENCE
#                             EACH OTHER, which is why they are published in one file: nothing in
#                             the compiler could otherwise notice a number used twice.
#                             Revision 1 recorded that this half was empty and that the front end
#                             which would mint it was JS-3b's. JS-3b wrote that front end, and
#                             revision 2 is the half.
# reason         the ONE core VmReason every emission of this code carries. A code emitted with
#                two reasons is a registry violation, not a code with two meanings. It is `-` on
#                every embedder-seam row, and that is not a gap: a rejection of source reaches no
#                core result, so there is no reason for it to carry and inventing one would be
#                claiming a transport the code does not use.
# stage          the pass that refuses. For the core-result half: header, manifest, framing,
#                limits, constants, code, entries, functions, modules, positions, reserved,
#                reader. For the embedder-seam half: tokenizer, parser, semantics, lowering.
#                `functions` arrived with format version 2, which is the first version to have a
#                function table. `modules` arrived with revision 8: it is the LINK, which runs
#                after every other structural pass and before the artifact is accepted, and it is
#                the only pass whose answer depends on the composition as well as on the bytes.
# reachability   corpus     a named entry of the retained corpus produces this code.
#                source     a named entry of the retained SOURCE corpus is refused with this code.
#                           The source corpus is src/tests/corpus/js-1/source/source.manifest, and
#                           it is to this half what the artifact corpus is to the other one.
#                defensive  no artifact reaches it at this build. The case column says why, and
#                           the count of these rows is fixed by rule N7 rather than by this file.
# case           the retained corpus entry that produces the code, the retained source entry that
#                is refused with it, or, for a defensive row, the reason no artifact reaches it.
# since          the registry revision in which this code acquired the meaning it has now. A code
#                is never reused for a different meaning: a rejection whose meaning changes takes a
#                new number and the old one is retired, which is what lets a corpus entry recording
#                a code be dated by the revision it was recorded under.
