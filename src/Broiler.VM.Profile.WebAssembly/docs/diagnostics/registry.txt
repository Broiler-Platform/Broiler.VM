# code|name|pass|carrier|reason|reachability|case|since
#
# code           the member's number. A code is never reused for another meaning: a refusal whose
#                meaning changes takes a new number, and the old one is retired and stays taken.
# name           the member of WebAssemblyDiagnosticCode that has that number.
# pass           every pass that emits the code, joined with `+`, in this order:
#                decode     WasmDecoder, which frames every section and reads every grammar except
#                           a function body's instructions.
#                validate   WasmValidator, which checks the module's index spaces and walks each
#                           function body once, decoding and typing each instruction in one step
#                           (draft decision WAD-0004).
#                hook       the family's verifier hook, WasmFamilyVerifier and WasmFamilyData, over
#                           a universal bytecode artifact's module definitions and at every family
#                           instruction.
#                translate  the lowering of a validated module into universal bytecode, WasmLowering
#                           and WasmTranslator.
#                execute    the family's execution, which maps a trap kind onto its code.
#                bare-module  the bare-module verifier milestone UBC-4 retired. Retired rows only.
#                The shared mapping in WebAssemblyDiagnostics.cs, WasmRefusal, is called by the
#                decoder and the validator both, so a code only it emits is `decode+validate`.
# carrier        where the code travels, joined with `+` when its passes use more than one:
#                translation  the translation's answer, in the fields the core's verifier outcome
#                             has - this code and a position record - and never in a core result.
#                             Every decode, validate and translate code.
#                outcome      the core's own code and reason pair on the verifier outcome, with the
#                             universal bytecode walk's position. Every hook code, and the two the
#                             retired bare-module verifier emitted.
#                payload      the typed payload of a ProfileFault, WebAssemblyTrap, beside the trap
#                             kind. The core's diagnostics have nowhere to put it.
# reason         the ONE core VmReason every emission of this code carries. A code emitted with two
#                reasons is a registry violation, not a code with two meanings. On a payload row it is
#                the reason the core gives every profile fault, ProfileFaultUnspecified, which the
#                profile does not choose. On a retired row it is the reason the code last carried.
# reachability   corpus     the case column names a derived entry of the corpus manifest: its answer
#                           was written down before the profile was asked, and it records an invalid
#                           artifact with exactly this code and this reason. Every entry recording
#                           the code records the same reason.
#                execution  the case column names a trap kind a named check of the harness root's
#                           execution lane expects. The check reads the trap's kind and its code off
#                           the payload, and holds the code to the execution checks' own table of
#                           this registry's codes, which rule W3 holds to these rows. It is weaker
#                           than `corpus` in one way, which is why it is its own word: the module is
#                           assembled by the harness at every run, and no bytes or answer are
#                           retained and pinned. *(Corrected 2026-09-28, the day revision 1 was
#                           written: this read "The check reads the trap's kind, and the code travels
#                           beside it, mapped from the kind by one switch in WasmFamily; no check reads
#                           the code off the payload." The checks read the code since. No row and no
#                           code's meaning changed, so the revision did not move.)*
#                hook-check the case column names a check of the harness root's hook lane
#                           (HookChecks.cs), which takes the artifact the translator wrote for a small
#                           module, alters one thing in it that the translator never would, hands it to
#                           the core's verification, and expects an invalid artifact with exactly this
#                           code and this reason. The expected answer is written beside the check before
#                           the core is asked. It is a check and not a corpus entry because every retained
#                           entry is a WebAssembly module, and the translator writes definitions the hook
#                           admits. *(Added 2026-09-29, with no new code and no changed meaning, so the
#                           revision did not move: twelve rows that read `unreached` name a check since.)*
#                unreached  no named case reaches the code, and the case column says why, in the
#                           words rule W3 lists. WHICH ROWS MAY SAY THIS IS FIXED BY THE RULE, not
#                           by this file. These rows are the part of WA-3's gate clause "every code
#                           in it is reachable from a named case" that is not met.
#                retired    nothing emits the code. The number stays taken.
# case           the corpus entry, the hook check, the trap kind, the rule's words for an unreached
#                row, or `-`.
# since          the registry revision the code was published in. The revision and this column date
#                a code's MEANING: a new corpus entry for an existing code moves neither.
#
# THE BAND TELLS THE PASS, NOT THE CATEGORY. Codes below 2700 are the decoder's, 2700 to 2849 the
# validator's, 2850 to 2869 the hook's own, 2870 to 2899 the translation's, 2900 to 2999 a defect of
# this assembly, and 3000 and up execution. A code the hook shares with the decoder or the validator
# keeps that code's number and reason. A malformation the validator meets inside a function body
# carries a 2800-band code with a malformation reason (UnknownOpcode, ReservedImmediateNotZero): the
# category a refusal names is its reason. Draft decision WAD-0004 records why.
#
# POSITIONS. Every carrier uses the core's position record, VmSourcePosition: a section index, a
# byte offset and two coordinates the core does not interpret. What this profile puts in them:
#   decode       section index: the ordinal of the section being read, counting every section framed
#                so far from 0, custom sections included, and -1 in the preamble. Byte offset: from
#                the start of the payload. Coordinate 0: the identifier of that section, and -1
#                between sections. Coordinate 1: the ordinal of the item in the section's vector,
#                and -1 outside one.
#   validate     section index: -1, which here means "the validator does not know section ordinals".
#                Byte offset: within a function body, from the first byte of its instructions, after
#                its locals; for a refusal about the module rather than a body, 0. Coordinate 0: the
#                identifier of the section the refused item came from. Coordinate 1: the item's
#                ordinal in that section, which for a body is its function index.
#   translate    as validate, with coordinate 0 the code section's identifier, 10. A defect answers
#                -1, 0, -1, -1.
#   hook         the universal bytecode walk's position in the artifact, which is the core's
#                convention and not this profile's.
#   payload      section index: 10, the code section's IDENTIFIER rather than an ordinal. Byte
#                offset: within the function's body. Coordinate 0: the function index. Coordinate 1:
#                the byte offset again. THIS DISAGREES WITH THE VERIFICATION PATH'S USE OF THE SAME
#                FIELDS and is recorded here as found: the trap payload keeps the retired executor's
#                layout. Choosing one layout is WA-5's, or an amendment to this registry.
#
# THE REVISION IS RECORDED WITH THE CORPUS. The core carries a revision for its own reason registry
# and none for a profile's, so this profile records it in the corpus manifest's header, as
# "# registry-revision: N", written by the harness root's writer from CorpusStore.RegistryRevision.
# Every entry in a manifest is dated by that line. Rule W3 holds the writer's constant to this
# file's revision, and a manifest's line to at most it.
#
# Held by rule W3 (src/tests/Broiler.VM.Architecture.Tests/WebAssemblyRegistryRules.cs) in both
# directions: every member of WebAssemblyDiagnosticCode has exactly one row and every row names a
# member of its number; every emission site in the profile assembly's source carries the row's
# reason and is in one of the row's passes, and each of the row's passes has a site; the carrier is
# the one its passes use; a corpus row's entry exists, is derived and records exactly this code and
# reason, and no entry records a code with another reason; a hook-check row's check expects exactly
# this code and reason; an execution row's trap kind is mapped to
# this code by the profile and by the execution checks' table, and a check expects it; the unreached
# rows are the ones the rule lists;
# and a retired row's code is named nowhere in the assembly's source.
