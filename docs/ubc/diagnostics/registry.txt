# published-at-milestone: UBC-1 (revision 1)

# corpus: src/tests/corpus/ubc-1/manifest.json
# format-version: 1
#
# code|name|reason|reachability|case|since
#
# code           the member's number. The universal bytecode's codes are the 3000 range, and the
#                hundreds group them the way the enumeration's own comments do: the header, section
#                framing, the Families section and FamilyData, Types and Units, the code walk,
#                regions, jump tables with entries and positions, the form layer, and the bounded
#                reader with the verifier itself. A code is never reused for another meaning.
# name           the member of UbcDiagnosticCode that has that number.
# reason         the ONE core VmReason every emission of this code carries. A code emitted with two
#                reasons is a registry violation, not a code with two meanings: a corpus triple that
#                recorded it would no longer identify what happened.
# reachability   corpus     the case column names an entry of the retained corpus that is pinned
#                           Exact and expects an invalid artifact with this code and this reason.
#                defensive  no artifact reaches it at this build, and the case column says why.
#                           WHICH ROWS MAY SAY THIS IS FIXED BY RULE U8 AND NOT BY THIS FILE: the
#                           rule lists them with their reasons, so a new defensive row is an edit to
#                           the rule's own list rather than to the file the rule reads. The corpus
#                           manifest's defensiveCodes says the same thing in the same words.
# case           for a corpus row, the id of the entry in the corpus manifest; for a defensive row,
#                why no artifact reaches the code.
# since          the registry revision the code was minted in. The revision and this column date a
#                code's MEANING: a new corpus entry for an existing code moves neither.
#
# ONE HALF. Every code here travels in a core verification result, in the profile diagnostic-code
# field, beside its reason and a position; none is a rejection of source. A family's hook answers
# with codes of its own registry, outside this range, and those rows are the family's to publish,
# not this file's.
#
# VerifierDefect IS A CORPUS ROW, although the enumeration's own comment calls it defensive. No
# artifact reaches it through a well-behaved family, and that is what the comment says; the corpus
# reaches it by replaying entries under hooks that break the hook contract on purpose - a hook that
# answers with a code of this range, and one that answers with no invalid-artifact reason - which
# the walk reports as a defect of its hook rather than passing on. The row names the first of them.
#
# Held by rule U8 (src/tests/Broiler.VM.Architecture.Tests/UbcRules.Registry.cs) in both
# directions: every member of UbcDiagnosticCode has exactly one row and every row names a member of
# its number; every emission site in the source of Broiler.VM.Ubc carries this row's reason; every
# corpus row's entry exists and expects exactly this code with this reason; and the defensive rows
# are the ones the rule lists.
