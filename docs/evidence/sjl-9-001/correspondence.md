# SJL-9.1's correspondence from code: locale data and the Intl algorithms in both engines

**Written:** 2026-10-26, at SJL-9.1 (work package SJL-9.1, task 1.1), as the input of the area verdict SJL-9.1 files
and of the two `sjl-9-001` rules, before any code of SJL-9.2 or later exists. The verdict takes the next free JSD:
the plan names it JSD-0081, a number SJL-11's verdict has since taken, so the filing fixes the number, and this file
names the verdict "the area verdict". The file covers the area's five sub-areas in the plan's order, each with its
row letters: (a) locale identifiers, likely subtags, negotiation, Locale info and `supportedValuesOf`, rows **L**;
(b) the Intl mathematical value, digit options and FormatNumericToString, then plural rules and plural ranges, rows
**M** and **P**; (c) number formatting, then list, relative time and display names, rows **N** and **S**; (d)
date-time formatting, intervals, day periods, hour cycles, zone names and Intl over Temporal, rows **T**, with row
**Z8**, which keeps its SJL-8 name; (e) duration formatting, rows **U**. **Every behavioural cell was run in both
engines.** **Each row carries its class**, one of the seven below, and no row's class is unknown. A class that rests
on a reading of the pinned text stands until the Intl vectors (SJL-9.2) check that reading; a reading they refute is
a finding against the area verdict, and the row is reclassified there.

**The classes.**
- **Same in both:** the two engines give the same answer (where both depart from the pinned text, the row says so).
- **Correction of Broiler.JS:** Broiler.JS's answer departs from the pinned text and Broiler.VM's does not; the shared
  library follows the text, and Broiler.JS's answer moves at SJL-9.5.
- **Correction of Broiler.VM:** the reverse; Broiler.VM's answer moves at SJL-9.4.
- **Implementation-defined:** the pinned text leaves the answer to the implementation (an implementation-defined
  abstract operation, a normative-optional clause, or an implementation- and locale-dependent value); the shared
  library keeps one answer, Broiler.VM's unless the row says otherwise.
- **Data policy (C5):** the answers differ by locale data: each engine's locale list under decision D5, CLDR's data
  against hand tables or the host's ICU, a CLDR release.
- **Engine policy (a parameter):** a policy each engine keeps through a parameter of the shared code: the default
  locale and zone, the available locales, the meter, an engine's own extension.
- **Code no input reaches:** the engines' code differs where no input of the engine's data or callers can reach it.
