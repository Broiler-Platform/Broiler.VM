# Milestone SJL-7 — Unicode character data and algorithms

[← Roadmap](../roadmap.md) · [Ledger](../status.md) · [Area design](../areas/unicode.md)

- **Objective.** One pinned owner supplies Unicode character data and algorithms to both engines,
  with exact ECMAScript property names, results that cannot be mutated, a public Unicode version, and
  caller-owned metering. The scope:
  - property lookup;
  - lexical classes;
  - case folding;
  - default and language-sensitive case mapping;
  - normalization;
  - properties of strings;
  - grapheme, word and sentence segmentation.

  Each engine's own Unicode code, and its use of host Unicode data, are gone. Its embedded tables
  are regenerated by the owner's generator ([SJL-D-6](../decisions.md#sjl-d-6) (c)).
- **Owner roles.** The Broiler.Unicode maintainer, or the Broiler.JS maintainer for any sub-area
  SJL-7.1 places in the Broiler.JS repository under [SJL-D-1](../decisions.md#sjl-d-1)'s rule. Also
  the JavaScript profile owner and the Broiler.JS maintainer. One person.
- **Repositories.** Broiler.Unicode, Broiler.JS, Broiler.VM. Broiler.RegEx is touched only where its
  case-folding data moves to the shared owner.
- **Waits on.** SJL-3. It applies two decisions taken on 2026-10-11:
  - [SJL-D-1](../decisions.md#sjl-d-1) (b): Broiler.Unicode is the home, under SJL-7.1's owner
    conditions;
  - [SJL-D-6](../decisions.md#sjl-d-6) (c): the owner holds the generator and the pins, and each
    engine embeds the tables they produce. This is the first data area, so its JSD records the
    decision.

**JSD-0031 §4(b) must be answered on evidence.** Broiler.VM's decision JSD-0031 §4(b) refused
`Broiler.Unicode.Properties` for five reasons:

1. rules A2 and N1 forbid the dependency;
2. its loose name resolution does not conform;
3. it has no decomposition or case-folding data;
4. its provenance cannot be reproduced;
5. its runtime cost.

This milestone answers each reason, as follows:

1. the admission path of SJL-2 answers the first;
2. an exact-name API answers the second;
3. added data answers the third;
4. pinned and hashed generator inputs answer the fourth;
5. each engine's own measurement under a predeclared rule answers the fifth.

**If any reason stands, the area is refused**, and JSD-0031 stands with it.

## Work packages

### SJL-7.1 — Area verdict, owner conditions and comparison rules

The area is placed with Broiler.Unicode if Broiler.Unicode adopts four things:

- the programme's conventions;
- a roadmap, filed at SJL-0;
- an assurance gate;
- generator inputs that are pinned and hashed.

Otherwise the area goes to the Broiler.JS repository, and the record says why. One verdict is filed
per sub-area:

- properties and lexical classes;
- case folding;
- case mapping;
- normalization;
- properties of strings;
- segmentation.

*(2026-10-16: filed as [JSD-0074](../../../src/Broiler.VM.Profile.JavaScript/docs/decisions/0074-unicode-moves-to-broiler-unicode-under-the-owner-conditions.md): all six sub-areas accepted and placed with Broiler.Unicode, which adopts
the four conditions by a dated record in its `docs/roadmap.md` and meets them in SJL-7.2; decision SJL-D-6
recorded; and the comparison rules committed in each repository's bundle `sjl-7-001` before any code.)*

### SJL-7.2 — The owner's preparation (Broiler.Unicode)

1. **Pinned inputs.** A pin file hashes the UCD 17.0.0 inputs: the same files Broiler.VM's
   `src/tests/unicode/pins/unicode.pin` names, the auxiliary break-test files included. The
   generators live in the repository: those Broiler.VM uses today (`UnicodeDatabase`,
   `UnicodeTableGenerator`), or ports of them. A byte-for-byte regeneration test is rule SL7.
   *(Corrected 2026-10-16, at SJL-7.1, by [JSD-0074](../../../src/Broiler.VM.Profile.JavaScript/docs/decisions/0074-unicode-moves-to-broiler-unicode-under-the-owner-conditions.md): Broiler.VM's segmentation tables and its
   Soft_Dotted table are written by `CldrTableGenerator`, from the same `UnicodeDatabase`, so the Unicode
   parts of that generator are ported too.)*
2. **Public data version.** A public `UnicodeVersion` constant. The emoji version claim in the
   README is corrected: the code carries 17.0.
3. **Exact property names.** A lookup that admits exactly the names and aliases ECMA-262's tables
   admit, `Katakana_Or_Hiragana` included. It returns immutable spans or sets. The existing loose
   lookup stays for its existing consumers, with a documented warning, until they move.
4. **Code-point lookups** for the properties both engines classify by: General_Category,
   ID_Start, ID_Continue (with Pattern_Syntax subtracted, as UAX #31 requires), White_Space and
   Soft_Dotted.
5. **Case folding.** `SimpleFold`, `Orbit`, and the non-Unicode canonicalisation with its upper
   orbit. Broiler.Regex's generated folding data and Broiler.VM's are identical today, so they
   become one generated table here.
6. **Case mapping.** Full mappings, and a language enumeration covering the default, Turkic and
   Lithuanian cases. It implements Final_Sigma and keeps lone surrogates. It takes a maximum result
   length and a meter. **It falls back to no host casing**: the current `JSStringSpecialCasing`
   delegates its simple mappings to `ToUpperInvariant` and `ToLowerInvariant`, and approximates
   Cased and Case_Ignorable from the runtime's categories.
7. **Normalization.** NFC, NFD, NFKC and NFKD, with a maximum result length and a meter, and lone
   surrogates passed through unchanged. **The method names avoid the identifier tokens rule N23
   rejects**, or N23 is re-scoped in the same change (see the area design).
8. **Properties of strings.** The emoji package is joined by the ECMAScript name map, which sits in
   Broiler.Regex today. `GetSequences` stops allocating on every call.
9. **Segmentation.** UAX #29 grapheme, word and sentence boundaries over the pinned break data, in
   an optional package, with a meter and ICU-style word statuses.
10. **Tests.** `NormalizationTest`, the three break tests, `CaseFolding`, `SpecialCasing`, and the
    ECMAScript property tables.
11. **Tables through a provider** ([SJL-D-6](../decisions.md#sjl-d-6) (c)). The owner's algorithms
    read their tables through a provider that hands them the generated bytes. Each engine embeds
    the tables the owner's generator produces from the pinned inputs, and passes them in; Broiler.VM
    generates from its own pin, which rule `I4` holds equal to the owner's. The
    owner's existing packages may keep shipping their own tables for their other consumers; neither
    engine references a package that carries tables.
12. **Native AOT** (convention 12). `IsAotCompatible` and `IsTrimmable` are declared and a Native
    AOT probe runs in the owner's CI. The packages already publish and run under Native AOT without
    a warning, but declare neither, so no consumer's trimming treats them as annotated.

### SJL-7.3 — Vectors

The corpus gains engine-level vectors for:

- `normalize`, `toUpperCase`, `toLowerCase` and `toLocale*Case`;
- `\p{…}` acceptance and membership, through `RegExp` engine-level rendering. **The regular-
  expression engines themselves are SJL-11's**;
- identifier acceptance, through `eval`- and `Function`-free rendering where possible;
- `Intl.Segmenter`.

**Unicode's own test files are the oracle at library level.**

### SJL-7.4 — Broiler.VM's cut-over

**Deleted:**

- from `Broiler.VM.Profile.JavaScript.Format`: the lookup code of `JsUnicodeProperties`,
  `JsUnicodeCaseFolding` and `JsUnicodeStringProperties`, and `JsUnicodeLexical`;
- from the profile: the code of `JsUnicodeNormalization` and `JsUnicodeCasing`;
- from `JsRealm.String`: the normalization passes and the language-casing helpers;
- the Soft_Dotted table in the Intl data, which the casing tables now carry;
- `JsSegmenter`'s algorithm;
- the platform classification that remains in `JsNumberFormat.IsWhiteSpace` (if any survived
  SJL-3), `FunctionIsNativeName` and `RegExpEscapeCodePoint`. *(Corrected 2026-10-16, at SJL-7.1, by
  [JSD-0074](../../../src/Broiler.VM.Profile.JavaScript/docs/decisions/0074-unicode-moves-to-broiler-unicode-under-the-owner-conditions.md): `JsNumberFormat.IsWhiteSpace` did not survive SJL-3.4, and the
  parser's five routing checks over `char.IsLetter`, `char.IsWhiteSpace` and `char.IsLetterOrDigit` join
  the list.)*

**Regenerated, not deleted** ([SJL-D-6](../decisions.md#sjl-d-6) (c)): the generated tables, which
are the `.g.cs` files of the classes above and the segmentation break tables. The owner's generator
produces them from the pinned UCD inputs, in the owner's format. They stay embedded where they are today:
Format for what the compiler and the runtime both read, the profile for the rest, and the optional
`.Intl` assembly for segmentation. They reach the owner's code through its provider.

**Generator and rules.** Broiler.VM's generator (`UnicodeTableGenerator` over `UnicodeDatabase`)
moves to the owner, which starts from a copy of Broiler.VM's pin. Rule N22 stays in Broiler.VM: it
regenerates the embedded tables with the owner's generator and holds them byte for byte under its
budget. *(Corrected 2026-10-16, at SJL-7.1, by [JSD-0074](../../../src/Broiler.VM.Profile.JavaScript/docs/decisions/0074-unicode-moves-to-broiler-unicode-under-the-owner-conditions.md): the segmentation
tables and Soft_Dotted are held by rule N28, in the Intl assembly, which regenerates them the same way under
its own budget; the matcher's reference to the owner from Format needs rule I1's allow-list widened for
Format, which today refuses an admitted package there.)* Rule `I4` checks that Broiler.VM's pin agrees with the owner's. The remarks and vacuity
guards of N23 and N18 are re-pointed. The profile, the compiler and the matcher reference the
owner's code packages, and the matcher's references stay until SJL-11 replaces the matcher.

### SJL-7.5 — Broiler.JS's cut-over

**Deleted or replaced:**

- the host `string.Normalize` in `JSStringPrototype.Transform` and in the collator's NFD step;
- `JSStringSpecialCasing` usage, and the `CultureInfo` resolution for locale casing. The locale maps
  to the language enumeration through Broiler.JS's own locale canonicalisation;
- `CharExtensions`' identifier classification and its Unicode-17 patch tables;
- the whitespace lists: the scanner's, `StringSpan.Trim`'s, and `JSRegExp.Escape`'s;
- `JSRegExp`'s identifier classes and its loose property lookup. The translator itself is SJL-11's;
- `JSIntl`'s `ComputeGraphemes`, `ComputeWords`, `ComputeSentences` and `IsWordLike`.

**The package dependency.** Broiler.JS references the owner's code packages directly, and embeds the
tables the owner's generator produces, as Broiler.VM does ([SJL-D-6](../decisions.md#sjl-d-6) (c)).
Today it uses `Broiler.Unicode.Properties` only transitively, through Broiler.Regex. *(Corrected 2026-10-16,
at SJL-7.1, by [JSD-0074](../../../src/Broiler.VM.Profile.JavaScript/docs/decisions/0074-unicode-moves-to-broiler-unicode-under-the-owner-conditions.md): transitively by package reference, but its code calls
both `Broiler.Unicode.Properties` and the emoji package directly. `NumberParser`'s white space is SJL-3's
shared set since SJL-3.5, and the white space of the scanner and `RegExp.escape` is this milestone's, which
revises Broiler.JS's record of SJL-5 that left it to SJL-14 and SJL-11.)*

**Corrections, listed (decision [SJL-D-16](../decisions.md#sjl-d-16)):**

- normalization no longer depends on the host's ICU, or does nothing under invariant globalization;
- lone surrogates no longer throw;
- casing no longer depends on the host culture;
- U+00AA and U+00BA are now Cased;
- identifiers subtract Pattern_Syntax;
- whitespace excludes U+0085;
- sentence and word segmentation follow UAX #29.

### SJL-7.6 — Evidence

As in SJL-3.6, plus three items:

- the owner's test-file runs;
- generation byte for byte;
- each engine's measurement for `normalize`, casing and identifier scanning under predeclared
  rules. This answers JSD-0031's fifth reason.

## Exit gate

**Component (owner) clauses.**

1. The owner meets the four conditions of SJL-7.1.
2. Every sub-area that was not refused is implemented with exact names, immutable results, a public
   version and metering.
3. Unicode's test files pass.
4. Regeneration is byte-identical.

**Broiler.JS clauses.**

5. The deletion list is absent.
6. No host Unicode API remains in the areas covered.
7. test262 per path meets the area rule.
8. Every correction is listed.

**Broiler.VM clauses.**

9. Rules `I1` to `I7` hold, and rule `I4` agrees with the pin.
10. Rules N22 and N28 regenerate the embedded tables with the owner's generator from Broiler.VM's pin,
    which rule `I4` holds equal to the owner's. Rules N18 and N23 are re-pointed. Each has its witnesses.
11. test262 in both forms meets the area rule.
12. Every root is published and run in three modes.
13. N22's and N28's size budgets hold for the regenerated tables, and the bundle restates them by
    citation.

*(Revised 2026-10-11, when SJL-D-6 was taken as (c). Clause 10 read "Rules N18, N22 and N23 are
re-homed as the decision chose, each with witnesses." Clause 13 read "The size budget is restated
by citation for the moved tables.")*

*(Revised 2026-10-16, at SJL-7.1, before any evidence of SJL-7 existed, by [JSD-0074](../../../src/Broiler.VM.Profile.JavaScript/docs/decisions/0074-unicode-moves-to-broiler-unicode-under-the-owner-conditions.md):
the segmentation tables and Soft_Dotted are written by Broiler.VM's `CldrTableGenerator` and held by rule
N28, not N22, so both clauses name both rules. Clause 10 read "Rule N22 regenerates the embedded tables with
the owner's generator from Broiler.VM's pin, which rule `I4` holds equal to the owner's. Rules N18 and N23
are re-pointed. Each has its witnesses." Clause 13 read "N22's size budget holds for the regenerated tables,
and the bundle restates it by citation.")*

- **Broiler.JS:** its area record.

## Does not do

- **It does not share collation.** That is SJL-17, under decision
  [SJL-D-24](../decisions.md#sjl-d-24) (c).
- **It does not replace either regular-expression engine.** That is SJL-11; this milestone only
  changes where the engines' Unicode data comes from.
- **It does not move a Unicode version.** The pin stays 17.0.0 unless a dated decision moves it.
